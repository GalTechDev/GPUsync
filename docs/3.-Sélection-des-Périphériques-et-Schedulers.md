# 3. Sélection des Périphériques et Schedulers

GPUsync offre une grande flexibilité pour interroger le matériel, choisir des cibles d'exécution précises et orchestrer des topologies multi-GPUs.

---

## Découverte du matériel : `list_gpus()`

GPUsync expose une fonction globale `list_gpus()` pour lister tous les processeurs de calcul (GPUs) disponibles sur le système :

```python
from gpusync import list_gpus

gpus = list_gpus()
for g in gpus:
    print(f"GPU: {g.name} | Backend natif: {g.backend} | Index: {g.index}")
```

La fonction renvoie une liste d'objets `GPUDeviceInfo` contenant :
- `name` : Nom du périphérique (ex: "Intel(R) UHD Graphics" ou "NVIDIA GeForce RTX 4090").
- `backend` : Le backend natif ("cuda" ou "opencl").
- `raw_device` : L'objet brut sous-jacent du pilote (`cupy.cuda.Device` ou `pyopencl.Device`).
- `index` : L'index physique de la carte.

---

## Cibler un GPU et un Backend : `Scheduler`

Par défaut, le `Scheduler` initialise un backend de manière automatique. Vous pouvez toutefois cibler un GPU précis (obtenu depuis `list_gpus()`) ou forcer un backend spécifique :

```python
from gpusync import list_gpus, Scheduler

gpus = list_gpus()
# Exemple : On veut utiliser le GPU NVIDIA (normalement CUDA) sous le backend OpenCL
target_gpu = [g for g in gpus if "nvidia" in g.name.lower()][0]

scheduler = Scheduler(gpu=target_gpu, backend="opencl")
scheduler.initialize()
```

- **`gpu`** : L'objet `GPUDeviceInfo` ou le périphérique brut à utiliser.
- **`backend`** (optionnel) : Force le backend à utiliser ("cuda" ou "opencl"). S'il n'est pas fourni, le scheduler s'initialise automatiquement sur le backend natif associé au GPU.

---

## Restreindre l'essaim : `SwarmScheduler`

Le `SwarmScheduler` regroupe l'intégralité des GPUs détectés sur la machine en un seul pool d'exécution. Vous pouvez restreindre cet essaim à une sélection personnalisée de périphériques :

```python
from gpusync import list_gpus, SwarmScheduler

gpus = list_gpus()
# On ne souhaite ajouter à l'essaim que les GPUs de type OpenCL
opencl_gpus = [g for g in gpus if g.backend == "opencl"]

swarm = SwarmScheduler(gpus=opencl_gpus)
swarm.initialize() # N'initialise et n'utilise que la liste fournie
```

---

## SwarmScheduler vs MultiDeviceScheduler

Bien que tous deux manipulent plusieurs GPUs, ils répondent à des besoins d'ordonnancement différents :

| Caractéristique | SwarmScheduler | MultiDeviceScheduler |
| :--- | :--- | :--- |
| **Niveau d'action** | **Grain Fin (Périphériques)** : Répartit l'exécution de chaque kernel individuel sur un pool de calcul. | **Grain Gros (Tâches/DAG)** : Répartit les étapes logiques d'un algorithme complet. |
| **Backend** | **Hétérogène** : Peut combiner des drivers CUDA et OpenCL sous le même scheduler. | **Neutre** : Contient un ensemble d'instances de `Scheduler` ou de `SwarmScheduler`. |
| **Usage dans le code** | Utilisé comme argument `scheduler` lors de l'appel d'un kernel. | Utilisé comme décorateur `@gpusync_pipeline(multi)`. |
| **Parallélisme** | Round-Robin de streams/queues matérielles. | Exécution parallèle asynchrone des nœuds indépendants du graphe (DAG). |

### Coopération des Schedulers (Exemple de Topologie)
Dans une machine avec 2 GPUs NVIDIA et 1 GPU Intel intégré :
1. Créez un `Scheduler` pour le GPU NVIDIA 0 (CUDA).
2. Créez un `Scheduler` pour le GPU NVIDIA 1 (CUDA).
3. Créez un `Scheduler` pour le GPU Intel (OpenCL).
4. Unifiez-les avec un `MultiDeviceScheduler` :
   ```python
   multi = MultiDeviceScheduler([sched_nv0, sched_nv1, sched_intel])
   ```
5. Dans votre `@gpusync_pipeline(multi)`, GPUsync lancera les étapes indépendantes en parallèle sur les trois schedulers.
