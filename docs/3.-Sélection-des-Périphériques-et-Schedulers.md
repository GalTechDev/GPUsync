# 3. Sélection des Périphériques et Schedulers

GPUsync offre une grande flexibilité pour interroger le matériel, choisir des cibles d'exécution précises (GPU ou CPU natif) et orchestrer des topologies multi-GPUs.

---

## Découverte du matériel : `list_gpus()`

GPUsync expose une fonction globale `list_gpus()` pour lister tous les processeurs de calcul (GPUs et processeurs LLVM CPU) disponibles sur le système :

```python
from gpusync import list_gpus

gpus = list_gpus()
for g in gpus:
    print(f"Device: {g.name} | Backend natif: {g.backend} | Index: {g.index}")
```

La fonction renvoie une liste d'objets `GPUDeviceInfo` contenant :
- `name` : Nom du périphérique (ex: "Intel(R) UHD Graphics", "NVIDIA GeForce RTX 4090", ou "Native CPU").
- `backend` : Le backend natif ("cuda", "opencl", ou "llvm").
- `raw_device` : L'objet brut sous-jacent du pilote (`cupy.cuda.Device`, `pyopencl.Device` ou `LLVMDeviceDummy`).

---

## Le Moteur CPU Natif : `LLVMDeviceManager` (`backend="llvm"`)

En plus des GPU NVIDIA (CUDA) et AMD/Intel (OpenCL), GPUsync intègre un backend CPU natif basé sur **LLVM** (`backend="llvm"` via `llvmlite`) :

```python
from gpusync import Scheduler
from gpusync.devices.llvm import LLVMDeviceManager, LLVMDeviceDummy

# Initialisation du moteur JIT LLVM sur le processeur hôte (CPU)
llvm_dev = LLVMDeviceManager(LLVMDeviceDummy(), num_queues=8)

# Exécution du kernel sur les cœurs CPU sans aucun GPU ni driver graphique requis !
res = mon_kernel(a_gpu, b_gpu, global_size=(1_000_000,), scheduler=llvm_dev)
```

---

## Restreindre l'essaim : `SwarmScheduler`

Le `SwarmScheduler` regroupe l'intégralité des GPUs détectés sur la machine en un seul pool d'exécution :

```python
from gpusync import list_gpus, SwarmScheduler

gpus = list_gpus()
opencl_gpus = [g for g in gpus if g.backend == "opencl"]

swarm = SwarmScheduler(gpus=opencl_gpus)
swarm.initialize()
```
