#Exceptions

All derive from gs.GpusyncError. Messages say what is wrong, where, and how to fix it.

ExceptionWhen
gs.KernelSyntaxErrorat decoration: construct rejected in the kernel, missing return type, source not found
gs.TypeMismatchat call time: an argument's type differs from the signature
gs.ShapeMismatchat call time: inconsistent shapes, unknown output dimension
gs.UnsupportedFeaturethe device cannot do an operation of the kernel (with compat="strict" or an explicit device=), or exceeds its group limits
gs.DeviceErrordevice not found, driver error, GPU lost
gs.OutOfMemorythe output cannot be allocated in main memory: give out=
gs.OutOfBoundsexplicit mode: out-of-bounds atomic write (also an IndexError)
gs.CompatibilityWarningwarning: the kernel runs somewhere other than planned (see Devices)
PythonVerified
import numpy as np
import gpusync as gs

@gs.kernel
def norm(x: gs.f32[:], m: gs.f32) -> gs.f32[:]:
    return x - m

try:
    norm(np.ones(3), 0.0)                    # float64 instead of float32
except gs.TypeMismatch as e:
    print(e)
# argument 'x': gs.f32[:] expected, got a float64 array. Use x.astype(np.float32),
# or @gs.kernel(cast='auto') to convert

@gs.kernel
def add(a: gs.f32["n"], b: gs.f32["n"]) -> gs.f32["n"]:
    i = gs.index()
    return a[i] + b[i]

try:
    add(np.ones(3, np.float32), np.ones(4, np.float32))
except gs.ShapeMismatch as e:
    print(e)                                 # add(): inconsistent dimension 'n': 'a' → 3, 'b' → 4

#Debugging

  • Compare with the interpreter. device="cpu" runs the kernel with the reference interpreter: same semantics as the GPUs, exact result, slow. A GPU / cpu:0 difference reveals a race between threads or a precision issue. For group kernels, the interpreter also reports concurrent accesses to shared memory.
  • Compare with NumPy. An element-wise kernel written with gs.* functions also runs in NumPy (kernel.py_func).
  • Read the generated code. kernel.source("cuda" | "opencl" | "wgsl" | "ir"); GPUSYNC_DUMP_DIR=folder writes each code when it is compiled, specialized variants included.
  • Machine diagnostic. python -m gpusync, gs.backends().
PythonVerified
x = np.random.rand(1000).astype(np.float32)
assert np.allclose(norm(x, 0.5), norm(x, 0.5, device="cpu"))
print(norm.source("ir"))

#Performance

  • The first call compiles the kernel for the device (from a few milliseconds to a few hundred for CUDA, cached on disk). Measure from the second call on.
  • Each call has a fixed cost (around 0.1 ms on Vulkan, more with OpenCL). A kernel doing little work per cell must process many cells; for a series of small kernels on Metal, Vulkan or DX12, gs.batch() submits them at once.
  • Keep results on the GPU: chain kernels on gs.Array values and read only at the end.
  • f32 rather than f64: consumer GPUs compute f64 16 to 64 times slower, when they do at all.
  • 64-bit integers: division and remainder are slow everywhere (emulated), very slow on Metal; gs.mulhi often lets you stay in 32 bits (Montgomery modular multiplication).
  • Size specialization. In an indexed kernel, a dimension that is not an axis of the output (the length t of a series, for instance) and is at most 1,024 becomes a constant of the compiled code: unrolled loops, local arrays in registers. Measured gain on a DTW: ×1.5 to ×40 depending on the GPU. At most 8 variants per kernel and device; changing the size of the output axes recompiles nothing. GPUSYNC_SPECIALIZE=0 disables it.
  • Groups and shared memory (see Thread groups) for anything that reuses neighbouring data.

#Known limits

  • No slices (x[a:b]) and no calls to your own functions inside a kernel.
  • No broadcasting between arrays of different shapes in an element-wise kernel.
  • Non-contiguous arrays (transposed or strided NumPy views): copied to contiguous memory at call time.
  • 64-bit gs.Out not allowed; grid= cannot be combined with group=.
  • Beyond 2³¹ − 1 elements in one array kept whole on the device: handled by OpenCL, CUDA and cpu:0 (a 64-bit index variant compiled on demand), rejected by wgpu (Metal, Vulkan, DX12).
  • A GPU lost by the driver (gs.DeviceError) is reopened on the next call, but the running computation is lost.
