Installation

GPUsync is not on PyPI yet: you build it from the repository. The build produces a native module (gpusync._core, written in Rust) and installs the Python package in editable mode.

#Requirements

macOSWindowsLinux
Rustrustuprustuprustup
Python≥ 3.10≥ 3.10≥ 3.10
C compilerXcode Command Line ToolsVisual Studio Build Tools, "C++" workloadgcc or clang

No GPU library is needed to build: drivers (OpenCL, CUDA) are loaded at startup when present, and a missing one only disables the matching backend.

#Build

Terminal
python3 tools/dev.py setup      # creates .venv, installs maturin, pytest, NumPy, then builds

After changing Rust code:

Terminal
python3 tools/dev.py build      # rebuilds the extension in .venv
python3 tools/dev.py test       # rebuilds, then cargo test, pytest and the diagnostic

Run scripts with the Python from .venv (.venv/bin/python, or .venv\Scripts\python.exe on Windows), or with python3 tools/dev.py run script.py.

The only runtime dependency is NumPy ≥ 1.22.

setup and build also install the graphics engine gpusync.gfx, which is a separate package (gpusync-gfx, folder gfx/, pure Python). If you only want the library, ignore it: everything works without it, and gs.gfx raises an ImportError that gives the install command. To add or remove it by hand:

Terminal
.venv/bin/python -m pip install --no-build-isolation --no-deps -e gfx
.venv/bin/python -m pip uninstall gpusync-gfx

From Python:

PythonVerified
import gpusync as gs

for st in gs.backends():                       # one status per backend: cuda, wgpu, opencl, cpu
    print(st.name, st.available, st.error)
for d in gs.devices():                         # usable devices
    print(d.id, d.name, d.kind, "f64" if d.f64 else "no f64")

cpu:0 always exists: it is GPUsync's reference interpreter, exact but slow, useful to check a result or to debug.

#CUDA and NVRTC

The CUDA backend compiles kernels with NVRTC, NVIDIA's runtime compilation library. Without it, gs.backends() says so and Vulkan takes over on the same GPU. Two ways to get it:

Terminal
pip install nvidia-cuda-nvrtc-cu12      # a library, not a compiler to install

or the CUDA toolkit. GPUsync looks for NVRTC in the nvidia-* pip wheels visible to Python, then in the toolkit and on the PATH. Compiled code (PTX) is cached on disk.

#Environment variables

VariableEffect
GPUSYNC_DEVICEdefault device, e.g. opencl, cuda:0, cpu (see Devices)
GPUSYNC_CACHE_DIRfolder of the compiled CUDA code cache
GPUSYNC_CACHE=0disables that cache
GPUSYNC_NVRTCexact path of the NVRTC library
GPUSYNC_NVRTC_DIRSfolders where NVRTC is looked for (separated by :, or ; on Windows); empty: do not look in pip wheels
GPUSYNC_SPECIALIZE=0disables size specialization (see Errors, debugging, performance)
GPUSYNC_DUMP_DIRwrites every generated code to this folder when it is compiled

#Tests

Terminal
python3 tools/dev.py test

Differential tests run each kernel on every device of the machine and compare the results with the interpreter. GS_EXPECT=metal,opencl (or vulkan,opencl…) makes the suite fail if one of these backends has no device, so that nothing is believed tested when it is not. The engine tests (gfx/tests) run with the others when the engine is installed, and are skipped otherwise.
