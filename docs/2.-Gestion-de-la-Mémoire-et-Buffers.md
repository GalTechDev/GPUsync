# 2. Gestion de la Mémoire et des Buffers (VRAM)

Pour surpasser les goulots d'étranglement de la bande passante CPU-GPU (liaison PCIe) et gérer les limites physiques de la VRAM (Memory Wall), GPUsync implémente un système d'allocation et de transfert asynchrone explicite via la classe `AsyncBuffer`.

---

## La classe `AsyncBuffer`

`AsyncBuffer` représente un tableau de données résidant physiquement en mémoire GPU (VRAM).
- **En OpenCL** : Encapsule un objet `pyopencl.Buffer`.
- **En CUDA** : Encapsule un objet `cupy.ndarray` associé à un contexte CUDA précis.

### Méthodes clés :
- **`AsyncBuffer.to_device(scheduler, host_data)`** : Alloue la mémoire sur la carte et y copie les données CPU de façon asynchrone (non-bloquante).
- **`AsyncBuffer.empty_like(scheduler, host_data)`** : Pré-alloue un espace mémoire vide en VRAM (idéal pour les buffers de sortie).
- **`overwrite(host_data)`** : Remplace les données d'un buffer VRAM déjà existant sans faire de nouvelle allocation (Memory Pooling).
- **`to_host()`** : Rapatrie les données de la VRAM vers la mémoire RAM hôte sous forme de tableau NumPy.

---

## L'Affinité de Mémoire (Memory Pinning)

Chaque `AsyncBuffer` créé garde une référence directe au composant matériel (`device_manager`) sur lequel il a été alloué :

```python
self.device_manager = device_manager  # CUDADeviceManager ou DeviceManager
```

Cette propriété est essentielle :
1. Les données sont physiquement stockées sur une seule carte.
2. Lorsque vous passez un ou plusieurs buffers à un kernel, GPUsync inspecte le premier argument (`args[0].device_manager`) et **planifie le calcul directement sur cette carte**.
3. Cela évite le déplacement inutile ou accidentel de données volumineuses.

---

## Transfert Automatique Inter-GPU (Pipelines)

Dans le cadre d'un algorithme multi-GPU complexe (défini par `@gpusync_pipeline` avec un `MultiDeviceScheduler`), il peut arriver qu'un kernel doive lire des buffers résidant sur des cartes différentes (ex: une variable `A` calculée sur le GPU 0, et une variable `B` calculée sur le GPU 1).

### Le mécanisme de copie inter-GPU :
Avant d'exécuter chaque étape (nœud du DAG), l'orchestrateur de pipeline de GPUsync compare le `device_manager` cible du kernel avec celui de chacun des buffers d'entrée :

```python
# Extrait de gpusync/pipeline.py
for i, val in enumerate(real_args):
    if isinstance(val, AsyncBuffer) and getattr(val, 'device_manager', None) != device_manager:
        host_val = await val.to_host()
        real_args[i] = await AsyncBuffer.to_device(device_manager, host_val)
```

1. **Détection** : Si un buffer est sur un GPU différent du GPU d'exécution cible.
2. **Copie asynchrone** : GPUsync rapatrie la donnée sur l'hôte (RAM CPU) puis la transfère sur le GPU cible de manière asynchrone.
3. **Exécution** : Le kernel peut s'exécuter en toute sécurité puisque toutes ses dépendances sont désormais sur la même carte.

---

## Contraintes hors-pipeline (Appels manuels)

Si vous appelez un kernel `@gpusync_kernel` manuellement en dehors d'un `@gpusync_pipeline` avec des buffers situés sur des cartes différentes :

- **Pas d'auto-transfert** : Le compilateur n'effectue pas de transfert automatique à la volée.
- **Règle d'exécution** : Le kernel s'exécutera sur le GPU de `args[0]`.
- **Comportement des drivers** :
  - **OpenCL** : Génère une erreur `CL_INVALID_CONTEXT` si vous tentez de lire un buffer associé à un autre GPU.
  - **CUDA** : Lève une exception de violation d'accès mémoire CUDA si le P2P (Peer-to-Peer) n'est pas supporté ou activé.
  
**Recommandation** : Pour tout calcul impliquant des transferts ou des exécutions croisées sur plusieurs GPUs, utilisez systématiquement le décorateur `@gpusync_pipeline`.
