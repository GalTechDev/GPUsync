# 4. Guide de Démarrage Développeur

Ce document vous guide pas à pas dans l'écriture de vos premiers scripts avec la bibliothèque GPUsync.

---

## 1. Philosophie : Compilation Juste-à-Temps (JIT)

GPUsync procède à une **Compilation Juste-à-Temps (JIT)**. Lorsque vous écrivez une fonction décorée avec `@gpusync_kernel`, le code ne s'exécute jamais en Python. Le framework lit votre code source, extrait son Arbre Syntaxique Abstrait (AST), et le **transpile** instantanément en code natif C++ (CUDA ou OpenCL) avant de l'injecter sur la carte graphique.

### Règles d'écriture fondamentales :
1. **Pas de bibliothèques externes** : N'utilisez pas de fonctions Python complexes (comme `import math` ou `numpy` dans le kernel).
2. **Arguments typés** : Les paramètres doivent posséder une annotation de type explicite (`int`, `float`, `list`).

---

## 2. Structure d'un Projet Standard

Un script GPUsync suit toujours le même cycle : **Initialisation -> Transfert RAM/VRAM -> Calcul GPU -> Retour RAM**.

### A. Initialisation du Scheduler

Le `Scheduler` gère la détection de vos cartes graphiques et charge les pilotes :

```python
import numpy as np
from gpusync import list_gpus, Scheduler, AsyncBuffer

def main():
    # Découverte automatique des GPUs
    gpus = list_gpus()
    if not gpus:
        raise RuntimeError("Aucun GPU disponible.")
        
    # Initialisation sur le premier GPU détecté
    scheduler = Scheduler(gpu=gpus[0])
    scheduler.initialize()
```

### B. Allocation des Données (Hôte vers Périphérique)

Vous devez transférer vos tableaux NumPy (RAM CPU) sur la carte graphique (VRAM) avec `AsyncBuffer.to_device` :

```python
    # Données CPU (RAM)
    a_cpu = np.ones(1_000_000, dtype=np.float32)
    b_cpu = np.ones(1_000_000, dtype=np.float32)
    
    # Transfert vers VRAM
    a_gpu = AsyncBuffer.to_device(scheduler, a_cpu)
    b_gpu = AsyncBuffer.to_device(scheduler, b_cpu)
```

## 3. Écrire son Premier Kernel (La Magie du `ctx`)

Sur un GPU, on lance des milliers ou des millions de petits processeurs virtuels appelés **threads** en parallèle. Chaque thread traite une case précise.

L'argument **`ctx` (Context)** représente l'identifiant unique (index absolu) du thread GPU qui est en train d'exécuter la fonction :

```python
from gpusync import gpusync_kernel

@gpusync_kernel
def addition_kernel(ctx: int, a: list, b: list) -> tuple:
    # ctx varie de 0 à (global_size - 1)
    # Chaque thread lit et calcule une case
    return a[ctx] + b[ctx]
```

### Règles de signature :
- **`ctx`** : Premier paramètre obligatoire, typé `int`.
- **Tableaux** : Les arguments représentant des `AsyncBuffer` doivent être typés `list`.
- **Scalaires** : Les constantes doivent être typées `int` ou `float`.
- **Return** : Utilisez `-> tuple` si vous retournez une ou plusieurs valeurs de même taille que la grille d'exécution. Les tableaux de sortie sont alloués automatiquement.

### Appel du Kernel :

```python
    # global_size=(1_000_000,) indique au GPU de lancer 1 million de threads
    resultat_cpu = addition_kernel(a_gpu, b_gpu, global_size=(1_000_000,), scheduler=scheduler)
    print(resultat_cpu) # Renvoie un tableau NumPy contenant les résultats rapatriés !
```

## 4. Graphe de dépendances asynchrones (`@gpusync_pipeline`)

Si vous chaînez plusieurs calculs, vous ne voulez pas rapatrier la donnée sur la RAM CPU entre chaque étape. Utilisez le **Planificateur DAG (Graphe Orienté Acyclique)** :

```python
from gpusync import MultiDeviceScheduler, gpusync_pipeline

# 1. Planificateur pour plusieurs GPUs
multi_sched = MultiDeviceScheduler([scheduler])

# 2. Définition du pipeline
@gpusync_pipeline(multi_sched)
def mon_pipeline(a, b, c):
    # Les étapes sans dépendance mutuelle s'exécutent en parallèle
    res1 = addition_kernel(a, b, global_size=(1_000_000,))
    res2 = addition_kernel(b, c, global_size=(1_000_000,))
    
    # "final" attendra la fin de res1 et res2
    final = multiplication_kernel(res1, res2, global_size=(1_000_000,))
    return final # Seul le résultat final est téléchargé sur le CPU
```

## 5. Mémoire Partagée (SRAM) et Opérations Atomiques

Pour accélérer les réductions ou histogrammes, GPUsync donne accès à la **Shared Memory** (SRAM), un cache ultra-rapide partagé entre tous les threads d'un même bloc :

```python
from gpusync import gpusync_kernel

@gpusync_kernel
def histogram_kernel(ctx: int, X: list, hist_out: list):
    local_idx = get_local_id(0) # ID du thread dans son bloc (0 à 1023)
    
    # 1. Déclaration de la mémoire partagée locale au bloc de threads
    local_hist = local_memory((256,), "int")
    
    # 2. Initialisation
    if local_idx < 256:
        local_hist[local_idx] = 0
        
    # 3. Barrière de synchronisation
    barrier(CLK_LOCAL_MEM_FENCE)
    
    # 4. Accumulation locale atomique
    val = X[ctx]
    atomic_add(local_hist[val], 1)
    
    barrier(CLK_LOCAL_MEM_FENCE)
    
    # 5. Report en VRAM globale
    if local_idx < 256:
        atomic_add(hist_out[local_idx], local_hist[local_idx])
```

## 6. Alignement Mémoire (Memory Coalescing)

Le matériel GPU lit la mémoire par lignes de 32 ou 64 octets consécutifs. Pour des performances optimales, préférez toujours les structures contiguës en mémoire (*Structure of Arrays* - **SoA**) aux structures de données imbriquées (*Array of Structures* - **AoS**) :

- **AoS (Mauvais)** : Accéder à un tableau 3D `(N, 3)` via `X[ctx * 3 + d]`.
- **SoA (Excellent)** : Transposer le tableau en Python `(3, N)` et y accéder via `X[d * N + ctx]`. Les threads consécutifs accèdent ainsi à des cases mémoires adjacentes, permettant au GPU de fusionner les requêtes.
