# 4. Guide de Démarrage Développeur

Ce document vous guide pas à pas dans l'écriture de vos premiers scripts avec la bibliothèque GPUsync.

---

## 1. Philosophie : Compilation Juste-à-Temps (JIT)

GPUsync procède à une **Compilation Juste-à-Temps (JIT)**. Lorsque vous écrivez une fonction décorée avec `@gpusync_kernel`, le code ne s'exécute jamais en Python. Le framework lit votre code source, extrait son Arbre Syntaxique Abstrait (AST), et le **transpile** instantanément en code natif C++ (CUDA ou OpenCL), en JIT CPU (LLVM) ou en assembleur PTX (NVIDIA).

### Règles d'écriture fondamentales :
1. **Pas de bibliothèques externes** : N'utilisez pas de fonctions Python complexes (comme `import math` ou `numpy` dans le kernel).
2. **Arguments typés** : Les paramètres doivent posséder une annotation de type explicite (`int`, `float`, `list`).
3. **Commentaires et Docstrings autorisés** : Les commentaires `#` et les docstrings `"""..."""` sont 100 % gérés et transpilés proprement en commentaires C++.

---

## 2. Démarrage Rapide : Traitement Out-Of-Core Monoligne (`map_out_of_core`)

Si vous avez un jeu de données géant (dépassant la VRAM), GPUsync permet de le traiter **en 1 seule ligne de code** :

```python
from gpusync import gpusync_kernel, Scheduler, list_gpus
import numpy as np

@gpusync_kernel
def process_signal(ctx: int, data: list) -> tuple:
    # Code exécuté en parallèle sur des millions de threads GPU
    return sqrt(data[ctx]) * 2.5 + 1.0

scheduler = Scheduler(gpu=list_gpus()[0])
scheduler.initialize()

# 1. Traitement direct d'un tableau NumPy géant
resultat = process_signal.map_out_of_core(large_dataset_50GB, scheduler=scheduler)

# 2. Traitement direct en STREAMING DISQUE via un Générateur Python (yield)
def stream_fichier_disque(filepath):
    with open(filepath, "rb") as f:
        while True:
            chunk = np.fromfile(f, dtype=np.float32, count=1_000_000)
            if len(chunk) == 0: break
            yield chunk

resultat_disque = process_signal.map_out_of_core(stream_fichier_disque("big.bin"), scheduler=scheduler)
```

## 3. Structure d'un Projet Standard

Un script GPUsync avec gestion manuelle de buffers suit le cycle : **Initialisation -> Transfert RAM/VRAM -> Calcul GPU -> Retour RAM**.

### A. Allocation des Données
```python
a_cpu = np.ones(1_000_000, dtype=np.float32)
b_cpu = np.ones(1_000_000, dtype=np.float32)

a_gpu = AsyncBuffer.to_device(scheduler, a_cpu)
b_gpu = AsyncBuffer.to_device(scheduler, b_cpu)
```

### B. Écrire son Premier Kernel (La Magie du `ctx`)
```python
@gpusync_kernel
def addition_kernel(ctx: int, a: list, b: list) -> tuple:
    return a[ctx] + b[ctx]

resultat_cpu = addition_kernel(a_gpu, b_gpu, global_size=(1_000_000,), scheduler=scheduler)
```

## 4. Partage de Mémoire Zero-Copy DLPack (PyTorch / CuPy)

`AsyncBuffer` implémente le protocole standard **DLPack** (`__dlpack__`, `from_dlpack`) pour partager des buffers VRAM sans aucune copie mémoire entre GPUsync, PyTorch, et CuPy :

```python
import torch
from gpusync import AsyncBuffer

# Import d'un Tenseur PyTorch sur GPU sans copie VRAM (Zero-Copy)
tensor_gpu = torch.randn(1_000_000, device="cuda")
async_buf = AsyncBuffer.from_dlpack(tensor_gpu, scheduler=scheduler)

# Export d'un AsyncBuffer GPUsync vers PyTorch sans copie
torch_tensor = torch.from_dlpack(async_buf)
```
